## Integrity / corrections-first disclosure

Leg C's first pass ran with a splice bug in this round's script: the
closing tail offset was e+9 where the correct length was e+11 (two
bytes short). The assert chain did not catch it (the truncated block
still contained one { and one }), so the "spliced" file still compiled
and leg C pass-1 returned gates = 1,634,722 = A1 exactly (i.e. the NOP
was effectively not applied), which the auto-delta block printed as
PER-LIMB = 0. I caught it in the delta output and re-ran leg C only,
with the corrected splice (verified on-disk: 1 C157 marker, 3 flat
checks present, brace balance intact). Pass-2 artifacts overwrite the
same filenames; the first-pass values above (C = 823,709) are the
authoritative RAN numbers, confirmed by fresh gates.json + caption +
identity 811,013+203,506=1,014,519. No corrupted state was left behind:
the spliced locus was restored byte-exact after both passes (SHA
re-pinned to 8e37436b…) and PORC=0.
